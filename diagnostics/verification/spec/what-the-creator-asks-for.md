# 我们请求上游提供的「可编目性」

> 给 Nowcast-in-a-Box 维护者。中文。
> 姊妹文档：`spec/data-access-we-ask-for.md`（**运行程序**要的接口）· 本文是**创建程序**要的。
> 相关：`interfaces/data.py` · `interfaces/model.py` · `adapters/catalog.json` · `contracts/`

## 一句话

**创建程序只读「声明」，不读「数据」，更不跑模型 —— 所以声明必须是完整、机读、可枚举的。**

```
系统配置（声明）  ──►  创建程序  ──►  检验配置（含路径）  ──►  运行程序
   ↑ 本文要的就是这一层：
     它必须够创建程序把配置写出来，而**不需要 import adapters 里的任何 Python**
```

## 创建程序做什么

给定平台**已经产出**的东西，产出一份检验配置：

1. **数一数有什么** —— 哪些数据源、哪些模型、哪些运行
2. **给每个源建一把尺子** —— 实况是谁、空间范围与分辨率、时间步长、单位
3. **筛出能配到一起的** —— 只有单位/形状/步长都对得上的模型才进名单
4. **把路径写进去** —— 实况和预报各在哪个目录
5. **写指标** —— 按族分组（`yes_no` / `continuous` / `spatial` / `moments`）

**它不读一个气象数据字节，也不加载 ONNX。**

## 一、现在已经够用的（保持住）

| 需要什么 | 上游有什么 | 状态 |
|---|---|---|
| 有哪些数据源 | `adapters/catalog.json` + `contracts/data/<id>.json` | ✅ |
| 有哪些模型 | `contracts/models/<data-id>/<model-id>.json` | ✅ |
| **模型和哪个数据源配对** | 声明里的 `data_adapter_id` —— **配对关系是数据，不是代码** | ✅ 很好 |
| 变量、类型、空间形状、帧数、步长 | `ChannelSpec.variables` / `native_cadence_minutes` / `output.spatial` | ✅ |
| 版本 | `version`（数据源和模型都有） | ✅ |
| 权重从哪来 | `weights.download_url` / `sha256` / `artifacts_relpath` | ✅ |

**上游自己写的那条要求，和我们需要的完全一样**：

> "A later job outside this repo should scan `contracts/data/*.json` and

> **It must not import adapter Python and must not install satpy.**"

**创建程序就是那个 job。** 建议把这句从 `TODO` 提到正式要求里。

## 二、三个真缺口

### ⚠️ ① 声明里没有**空间范围和分辨率** —— 建尺子必须要

现在能拿到的只有**形状**：

```json
"output": { "spatial": [128, 128] }        ← 128×128 个格点
```

但尺子需要的是：

```
这个 128×128 覆盖的是地球上哪一块？（西/南/东/北）
每个格子多少度？（分辨率）
```

`DataCapabilities.spatial` 只有 `crop` 和 `bbox_order`，**没有范围和分辨率**。
而 SEVIR 的 `region.bbox` 是**请求里给的**（`[0.0, 0.0, 1.0, 1.0]`），不是数据的声明 —— **方向反了**。

**没有这个，我们建不出尺子**，只能拿"模型自己的网格"当尺子，那是错的：
**尺子必须是实况的网格**，模型的重采样由我们做。

**要求**：`contracts/data/<id>.json` 里声明**范围（bbox）和分辨率**。
有 `crop` 的源（CMA 雷达）还要声明**可裁剪范围**。

### ⚠️ ② 运行的产出没有**可枚举的布局** —— 这是最大的缺口

创建程序要把**路径**写进配置，所以它必须能回答：

```
平台跑过哪些运行？（模型 × 数据源 × 起报时刻）
每一次的预报写在哪个目录？什么格式？
```

上游现在**没有**：

- `config.yaml` 里 `paths.runs: runs` 的注释是 *"One directory per **diagnostics** invocation"* —— 那是**诊断**的目录，不是模型运行的
- 「Persistent workspace」是 gitignored，**布局没有文档**
- `predict()` 返回内存里的 `Forecast` 就结束了，**没有任何地方说它被写到哪**
- 唯一提到路径的是 diagnostics 请求里的 `forecasts: [{id, path}]` —— 说明**确实会落盘**，但**那个约定没有写下来**

**要求**（和 `data-access-we-ask-for.md` 第六节是同一件事的两面）：

```
一次运行  =  一个目录
目录里有  一个清单文件，写明：模型 id / 数据源 id / 起报时刻 / 预报文件（可多个）
预报文件  格式固定、可被机读（不需要 import 适配器就能读）
```

**这条定下来，创建程序才知道往配置里写什么路径。**

### ⚠️ ③ `open` 模式的源**没有变量和单位可读**

`ChannelSpec.variables` 只在 `mode = "closed"` 时非空。
`open` 的源，创建程序**拿不到它提供哪些变量、什么单位** —— 于是既建不了尺子，也筛不了名单。

**要求**：不管 `open` 还是 `closed`，**都要能声明"我提供哪些变量、什么单位"**。
`open` 可以表达成"这些是我知道单位的，其余的不保证"，但不能**什么都不说**。

## 三、一条要保持的性质：**声明稳定**

我们的尺子有"指纹"（`ruler_fingerprint`）—— 一把尺子改了，就是另一组检验，新旧分数不可比。

这依赖声明的稳定性：

```
同一个 id + 同一个 version   ⇒   同一把尺子
改了范围/步长/单位           ⇒   version 必须变
```

**要求**：声明里的 `version` 是**语义版本**，不是"最近改过的时间戳"。
改任何一个会影响检验结果的字段（单位、步长、范围、变量名），**version 就得动**。

**否则我们会把两组不可比的分数画在一张图上，而且看不出来。**

## 四、明说不要的东西

| 不要 | 为什么 |
|---|---|
| 要求创建程序 import `adapters/*` 里的 Python | 那些文件会拉 satpy / h5py / onnx；创建配置不该装这些（上游自己也这么要求） |
| 要求创建程序**打开数据文件**才能知道有哪些变量 | 那是声明该说的 |
| 要求创建程序**跑模型**才能知道输出形状 | `output` 声明里有 |
| 把"有哪些运行"放在**代码**里（要执行才知道） | 必须能**当数据读** |
| 让配对关系藏在 `validate_input()` 的**实现**里 | 现在 `data_adapter_id` 是数据 ✅ 保持这样 |

## 五、验收：一个不看代码就能过的测试

```
给定一个仓库的声明文件（contracts/ + adapters/catalog.json），
不 import 任何 adapters Python、不装任何卫星库、不读任何数据文件，

创建程序应当能列出：
  · 每个数据源：变量、单位、步长、空间范围、分辨率、版本
  · 每个模型：它配哪个数据源、输出维度/形状/帧数、权重地址与校验和
  · 哪些 (实况, 模型) 组合是合法的，不合法的**各自给出理由**

并且能产出一份**格式合法的检验配置**。
```

**再加一条反向验收**：拿一份**改了分辨率但没改 version** 的声明，
**创建程序应当拒绝**（或至少报一个明确的警告）—— 见第三节。

## 六、和姊妹文档的关系（一句话分清）

| | 创建程序要的（本文） | 运行程序要的（另一份） |
|---|---|---|
| 看什么 | **声明**：有哪些源/模型/运行，各自什么性质 | **数据**：按名字+时间+时效取一个场 |
| 什么时候 | 配置**生成**时，一次 | 配置**执行**时，每个任务 |
| 最大的缺口 | **分辨率** 和 **run 输出布局** | **场不带坐标/单位**、**缓存责任** |

**两份合起来，就是我们这个模块对上游的全部依赖。**
