Verification configs

One config fixes three things: the ruler (what is compared, on which grid, at what step), the roster (which members, over which dates), and the metrics. The ruler cannot be edited — a change to it needs a new config, because the numbers before and after would not be comparable.

1Identity

A name for the config, and a note about why it exists.

Becomes the file name. Letters, digits, dashes, underscores.

2The ruler

Fixed for the life of the config. The truth source, the grid, the step and the unit together decide the denominator and the mask, so changing any of them changes what the numbers mean.

Must match every member, or nothing is computed.
Not interpolated at run time — the cadence is fixed.

3The roster

Which members this config verifies, and over which dates. Membership is what changes over time — a member is added or has a last day, and the record is kept either way.

4The metrics

Grouped by family, because everything in a family shares one set of parameters and is accumulated in the same pass. Levels and windows are parameters, not separate metrics: adding a threshold adds rows, adding a metric does not.

Comma separated. Only the families that need them.
In grid cells, for the neighbourhood metrics.

5Preview, then save

The preview plans against the runs this server can see. It does not read a single field, so it is cheap; switch on probe the provider to also ask which frames actually exist.
